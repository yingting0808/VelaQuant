# VelaQuant 用户手册

最后核对日期：2026-06-15

这份手册面向使用者，不面向开发者。它按 Web UI 的页面和日常工作流说明：每天看什么、点什么、系统背后怎么运行、能帮你得到什么结果，以及哪些能力还在研发中。

> 重要提醒：VelaQuant 当前处于受控模拟盘阶段。系统可以帮助你产生候选、解释原因、模拟下单、记录盈亏、复盘策略和验证 Alpha，但不保证收益，也不会自动实盘下单。

## 1. 这套系统能帮用户做什么

VelaQuant 的目标不是让 AI 直接喊单，而是帮用户建立一条可复盘、可验证、可进化的交易研究流程：

```text
发现候选
  -> 解释为什么值得关注
  -> 在模拟盘下单
  -> 记录订单和盈亏
  -> 复盘策略是否有效
  -> 判断是否继续、隔离、淘汰或进入下一阶段
```

它能帮用户解决这些问题：

| 用户问题 | VelaQuant 如何帮助 |
| --- | --- |
| 今天应该看哪些股票？ | 从自选股、组合、行情、公告、策略信号中生成候选池 |
| 为什么这个标的被选出来？ | 给出候选解释、证据、策略来源、排名分数和风险提示 |
| 能不能先不真买，跑一段时间看看？ | 用 paper trading 模拟下单、持仓、盈亏和复盘 |
| 策略到底有没有优势？ | 用 Alpha 门禁检查样本量、期望值、闭环交易和回撤 |
| AI 的建议会不会乱下单？ | AI 只做投研解释，不生成可执行订单，不调用执行链 |
| 每天要不要手动盯很多东西？ | APScheduler 会按交易日自动跑模拟盘，用户主要看日报和行动计划 |
| 哪里出问题了能不能追溯？ | Event Ledger 记录候选、风控、订单、解释和复盘事件 |

## 2. 每天应该怎么用

推荐日常流程分三段。

### 2.1 每天第一次打开系统

1. 打开 `http://127.0.0.1:3000/paper-trading`。
2. 先看“今日简报”。
3. 看 `健康状态` 是否为 ready。
4. 看 `建议` 字段。
5. 看 `Alpha 剩余` 和 `门禁缺口`。
6. 如果建议是 `hold_until_next_session`，说明当前交易日已处理完，等待下一次有效调度即可；同时看“预计推进”，确认下一次运行会补哪个 Alpha 样本缺口。
7. 如果出现需要复盘的行动，先看“行动计划”和“策略复盘记录”，再执行。

你每天最重要看的不是涨跌，而是：

- 今天模拟盘有没有正常运行。
- 有没有生成候选。
- 有没有成交订单。
- 有没有闭环交易。
- 期望值是否持续为正。
- 是否出现评分和盈亏反向。
- Alpha 门禁还差多少样本。

### 2.2 美股收盘后或次日早上

系统调度器会在设定时间运行 paper trading loop。当前运行态下一次有效采样会按 NYSE 交易日判断，不是每个自然日都交易。

用户要做：

1. 打开“每日调度”，确认下一次有效采样时间。
2. 打开“运行账本”，确认最近一次运行是 completed、skipped 还是 failed。
3. 打开“事件账本”，确认事件链是否可回放。
4. 打开“模拟订单”和“模拟持仓”，看订单是否成交、是否被风控拒绝、持仓是否触发止盈/止损。
5. 打开“复盘策略”和“净期望趋势”，看策略是否仍在积累正期望样本。

### 2.3 每周或阶段性复盘

1. 打开 `/strategy-lab`。
2. 查看“策略注册表”，确认哪些策略接入了 paper runtime。
3. 查看“策略竞争层”，确认策略排名、样本和推荐动作。
4. 查看“Alpha 验证”，确认是否仍被样本量或质量门禁阻断。
5. 需要时运行 LEAN 回测或候选池回测。
6. 把重要结论保存到“研究笔记”。

阶段性目标不是马上实盘，而是让模拟盘连续产出可解释、可复盘、净期望稳定的样本。

## 4. 总览

入口：`/`

总览页适合每天快速扫一眼。

你会看到：

- 组合市值。
- 持仓数量。
- 待处理预警。
- 组合暴露表。
- 事件预警。
- 右下角可展开的 AI 助手。

用户可以做什么：

1. 看组合是否过度集中。
2. 看是否有公告或事件需要处理。
3. 展开 AI 助手，让它解释当前页面或识别组合风险。

背后逻辑：

- 页面读取 dashboard API。
- 持仓和事件作为上下文，供 AI 助手生成研究解释。
- AI 解释不改变订单、持仓或风控。

能达到的效果：

- 快速知道今天组合有什么值得关注。
- 快速把页面信息转成可读的投研摘要。

## 5. 自选股

入口：`/watchlist`

自选股页用于维护系统长期关注的股票池。

你会看到：

- 自选股列表。
- 每个 ticker 的投资假设。
- 市场快照。
- 可查询任意 ticker。

用户可以做什么：

1. 添加一个 ticker。
2. 写下为什么关注它。
3. 查看默认股票或指定 ticker 的市场快照。
4. 删除不再跟踪的标的。

背后逻辑：

- 自选股会进入研究和候选生成上下文。
- 市场快照通过数据源抽象层获取，优先使用可用数据源，失败时 fallback。
- OpenBB 可提供 quote、history、fundamentals，但不能下单。

能达到的效果：

- 把零散想法沉淀成系统可跟踪的 watchlist。
- 让候选生成不再是拍脑袋，而是围绕已定义关注池运行。

## 6. 组合

入口：`/portfolio`

组合页用于维护本地组合账本。

你会看到：

- 当前组合名称。
- ticker、数量、成本等持仓字段。
- 新增、更新、删除持仓的表单。

用户可以做什么：

1. 添加持仓。
2. 修改持仓数量或成本。
3. 删除过期持仓。
4. 用组合数据作为 AI 风险识别和策略分析上下文。

背后逻辑：

- 组合持仓进入风险、权重、集中度和 AI 解释上下文。
- 模拟盘账户和组合页不是同一个账本：组合页是本地组合信息，模拟盘是 paper account。

能达到的效果：

- 让系统知道你当前关心的组合结构。
- 让 AI 助手和风险分析不脱离真实持仓背景。

## 7. 预警

入口：`/alerts`

当前状态：基础展示，研发中。

预警页目标是集中处理组合相关事件，例如：

- SEC filing。
- 财报日历变化。
- 组合相关重大事件。
- 需要人工复核的风险提示。

当前能做：

- 显示示例预警工作区。
- 作为未来事件处理中心的入口。

研发中能力：

- 真实预警队列。
- 预警确认、关闭、升级。
- 与研究笔记、候选池、AI 解释联动。

未来能达到的效果：

- 不用在多个页面找事件。
- 每个事件都能进入“查看 -> 解释 -> 复核 -> 记录”的流程。

## 8. 研究笔记

入口：`/notes`

研究笔记页用于沉淀投研判断。

你会看到：

- 已保存的研究笔记。
- 新建笔记表单。
- ticker、标题、正文。

用户可以做什么：

1. 手动写研究笔记。
2. 从 AI 助手结果点击“保存为笔记”。
3. 保存对某个 ticker 的复盘、风险或操作假设。

背后逻辑：

- AI 保存笔记会调用后端 `/api/mvp/research/notes`。
- 笔记会保存在数据库里。
- 笔记是研究记录，不会触发订单。

能达到的效果：

- 把每天的判断保存下来。
- 后续复盘时知道当时为什么关注或放弃某个 ticker。

## 9. 模拟盘

入口：`/paper-trading`

模拟盘是当前最重要的页面。它的目标是每天稳定产生候选、解释原因、模拟下单、记录盈亏、复盘策略。

页面现在按工作流拆成五类，不需要从上到下翻完整页：

| 分类 | 主要用途 |
| --- | --- |
| 总览 | 看今日状态、账户概览、行动计划、交易日和日报 |
| 事件与AI | 默认打开；看市场事件、具体事件内容、AI 分析边界、K 线和事件账本 |
| 候选与模拟 | 看候选池、模拟订单、模拟持仓、执行诊断和多日模拟 |
| 风控与复盘 | 看 Alpha 门禁、净期望、风险配置、风险限额评审和策略复盘 |
| 运行维护 | 看调度器、运行健康、稳定趋势和运行账本 |

### 9.1 模拟盘控制台

你会看到：

- 默认模拟盘账户。
- 运行今日模拟按钮。
- 当前同步状态。

用户可以做什么：

- 在系统允许时手动运行今日模拟。
- 在系统已经完成今日运行时查看结果，等待下一交易日。

背后逻辑：

- 手动运行和定时运行走同一条 paper trading loop。
- 不触达真实券商。
- 净期望未稳定前不进入实盘。

### 9.2 今日简报

今日简报是每天第一眼应该看的区域。

重点字段：

| 字段 | 解释 |
| --- | --- |
| 交易日 | 系统按 NYSE 日历识别的有效交易日 |
| 运行 | 今日 paper loop 状态 |
| 建议 | 系统给出的下一步动作 |
| 可下单 / 订单 | 候选中能下单的数量和已生成订单数量 |
| 权益 | paper account 当前权益 |
| 今日 PnL | 当天模拟盈亏 |
| Alpha | 是否达到 Alpha 验证标准 |
| 有效采样 | 下一次真正会收集样本的时间 |
| Alpha 剩余 | 预计还需要多少次有效样本 |
| 预计推进 | 下一次 paper run 预计会推进的 Alpha 门禁，例如闭环交易样本从剩余 3 笔降到 1 笔 |

背后逻辑：

- 系统合并 paper run、orders、positions、reviews、alpha gates 和 scheduler 状态。
- 今日简报不只看行情，还看策略是否在正确收集验证样本。

能达到的效果：

- 用户不用翻多个表，就能知道今天系统是否正常、还差什么、下一步做什么。

### 9.3 行动计划

行动计划告诉用户下一步最应该做什么。

常见动作：

- `hold_until_next_session`：等待下一次有效交易日采样。
- `continue_paper_validation`：记录当前 Alpha 验证快照。
- `review_score_pnl_inversion`：复盘评分和盈亏反向的 ticker。
- `apply_paper_risk_limit_recommendation`：只调整 paper 风险限额，不改变 live 限额。

背后逻辑：

- 系统会根据 Alpha blocker、运行健康、风控限制、事件账本和复盘状态生成首要动作。
- 行动计划不会越过 live/broker 禁用状态。
- 如果下一次 paper run 已经有可能触发退出样本，行动计划会展示结构化“预计推进”，例如“闭环交易 +2 笔，剩余 3 到 1 笔”。这表示系统预计下一次有效采样会补上 2 笔闭环交易样本，但仍要等实际运行和落库后才算正式通过。

能达到的效果：

- 用户每天不用猜下一步，先看行动计划即可。
- 用户能提前知道继续等待是否有意义，以及下一轮会具体推进哪个 Alpha 门禁。

### 9.4 候选池

候选池展示系统认为值得模拟验证的股票。

你会看到：

- ticker。
- 来源策略。
- 动作。
- 置信度。
- 建议数量。
- 证据摘要。
- 风险提示。
- 模拟买入按钮。

背后逻辑：

- 候选来自 Strategy Registry 控制的策略。
- 每个候选会保存 `strategy_id` 和 `candidate_id`。
- 候选解释会写入 `trade_explanation` 事件。
- 从候选发起的模拟买入会把 candidate id 带到订单里。

能达到的效果：

- 后续复盘时可以追踪“哪个候选理由导致了哪笔订单和盈亏”。

### 9.5 模拟订单

模拟订单展示 paper orders。

你会看到：

- ticker。
- 买卖方向。
- 数量。
- 成交价。
- 状态。
- 风控结果。
- Trading Core 状态机。

背后逻辑：

```text
TradeIntent
  -> RiskEngine
  -> ExecutionEngine
  -> OrderState
```

如果风控拒绝，订单不会进入成交状态。

能达到的效果：

- 用户可以知道订单为什么成交、为什么拒绝、在哪个状态停住。

### 9.6 模拟持仓

模拟持仓显示 paper account 当前持仓。

你会看到：

- ticker。
- 数量。
- 平均成本。
- 市值。
- 未实现 PnL。

背后逻辑：

- 模拟订单成交后更新持仓。
- 持仓会进入止盈/止损观察。
- 退出订单会继承最近的候选 ID，用于闭环归因。

能达到的效果：

- 用户可以看到模拟盘当前承担了哪些风险。

### 9.7 事件账本

事件账本用于追踪系统到底发生了什么。

在 Web UI 里，先进入：

```text
模拟盘 -> 事件与AI -> 市场事件中心
```

如果你关心 `SPCX` 或 `INTC`，在同一块区域的标的下拉框里切换 ticker。页面会同步刷新 K 线和市场事件中心。

你会看到：

- 总事件数。
- 最新运行事件。
- 完整链。
- 断链。
- 市场事件。
- 候选解释。
- 排名分数。
- 回测收益。

市场事件中心会把一条市场事件后面发生的事情串起来：

| 字段 | 意思 |
| --- | --- |
| 市场事件 | 系统从行情、研究证据或策略输入中结构化出来的事实 |
| 策略 ID | 哪个已注册策略读取了这个事件 |
| 置信度 | 该事件作为策略输入的可信程度，不等于盈利概率 |
| 影响分 | 该事件对候选排序或策略输入的重要程度 |
| 交易意图 | 策略是否产生了 `buy` / `sell` 意图 |
| 风控 | `RiskEngine` 是否放行 |
| 订单 | 是否进入模拟订单状态机，是否成交或拒绝 |
| 解释与证据 | 为什么产生候选或交易意图，包含来源、回测或排序证据 |
| 本事件依据 | 这条 MarketEvent 自己的来源内容，例如投研证据或 20/50 日均线快照 |
| 证据来源与内容 | 每个事件 topic 中保存的证据标题、摘要、来源、观察时间和链接 |
| 具体事件内容 | 每个 topic 的人可读说明；原始 payload 可作为次级信息展开 |
| correlation_id | 用来追溯同一条链路里的所有事件 |

背后逻辑：

系统把核心事件落库：

```text
market_event
strategy_input
trade_intent
risk_decision
order_state
trade_explanation
strategy_review
scheduler_decision
```

能达到的效果：

- 用户能追溯候选、风控、订单、复盘，而不是只看到一个盈亏数字。
- 用户能回答“INTC 今天为什么有/没有形成交易意图”“SPCX 有没有被风控挡住”“这笔模拟订单由哪条市场事件触发”。
- 用户能先看“本事件依据”确认事件来源，再展开具体事件内容查看完整 payload。

注意：评分/盈亏背离复盘是按策略生效，不是永久拉黑某只股票。比如默认证据评分策略在 AMZN 上出现背离，系统会阻止这个策略继续把 AMZN 当作已验证 Alpha，但另一个独立策略仍可以在同一 ticker 上收集自己的模拟样本。

### 9.8 Alpha 门禁和 Alpha 预测

Alpha 门禁告诉用户策略是否有足够证据。

当前主要门禁：

- 复盘天数。
- 连续正期望。
- 成交订单样本。
- 闭环交易样本。
- 回撤。
- 评分和盈亏是否反向。
- 是否有真实历史回测证据。

背后逻辑：

- 系统不会因为一次回测好看就允许进入下一阶段。
- 必须在模拟盘中持续产生真实运行样本。

能达到的效果：

- 防止策略样本太少时过早实盘化。

### 9.9 风险配置和风险限额评审

你会看到：

- 单笔上限。
- 仓位权重上限。
- 每日订单上限。
- 止盈。
- 止损。
- 风险限额建议。

背后逻辑：

- RiskEngine 是强制门禁。
- Paper 风险限额可以调整以收集足够样本。
- Live 限额不会被自动改变。

能达到的效果：

- 在模拟阶段加快样本收集，同时保持实盘关闭。

## 10. 策略实验室

入口：`/strategy-lab`

策略实验室用于回答：哪些策略值得继续跑，哪些还只是研究候选，哪些可以进入下一阶段。

### 10.1 回测环境

你会看到：

- Docker CLI。
- Docker Compose。
- Docker engine。
- LEAN Docker image。
- LEAN CLI。
- vectorbt。

如果全部可用，就可以运行回测。

背后逻辑：

- LEAN 用于更专业的策略历史回测。
- vectorbt 用于快速研究 replay。
- 二者都不替代 Trading Core。

### 10.2 LEAN 回测

用户可以做什么：

1. 选择策略。
2. 设置 ticker、日期、资金、均线参数等。
3. 运行回测。
4. 查看收益、夏普、回撤、交易次数、数据质量。
5. 查看回测历史。

背后逻辑：

- 当前 LEAN 可使用 OpenBB/yfinance 历史数据。
- 回测结果会成为策略研究证据。
- 回测不会直接触发模拟或实盘订单。

能达到的效果：

- 在进入 paper runtime 前，先用历史数据筛掉明显无效的策略。

### 10.3 策略注册表

策略注册表说明哪些策略能进入运行态。

当前已接入：

- `deterministic_watchlist_v1`
- `moving_average_cross`

背后逻辑：

- 策略必须通过 Registry 才能进入执行链。
- Registry 会读取回测、Alpha、订单样本等证据。

能达到的效果：

- 避免随便写一个策略就绕过系统下单。

### 10.4 策略竞争层

策略竞争层用于比较多个策略。

你会看到：

- 策略池数量。
- 可分配策略数量。
- 排名。
- 推荐动作。
- allocation weight。
- 阻断原因。

当前状态：

- 已有策略竞争和排名展示。
- 资金分配和 live allocation 仍受门禁限制。

能达到的效果：

- 逐步从“单策略运行”走向“策略池优胜劣汰”。

### 10.5 策略生命周期

目标生命周期：

```text
paper -> shadow -> live-small -> live -> killed
```

当前状态：

- 当前阶段为 paper。
- Shadow、live-small、live 仍未开放执行。
- broker execution 关闭。

页面上可能看到 Shadow 和 Live-small 区域，它们用于准备未来流程。

状态说明：

| 阶段 | 含义 | 当前状态 |
| --- | --- | --- |
| paper | 模拟盘运行和验证 | 已启用 |
| shadow | 影子观察，不真实下单 | 研发中 / 门禁未开启 |
| live-small | 小资金实盘试运行 | 研发中 / 门禁未开启 |
| live | 正式实盘 | 研发中 / 未开启 |
| killed | 策略停用 | 已有人工停用入口，但需满足条件 |

### 10.6 归因分析

归因分析用于解释盈亏从哪里来。

你会看到：

- 信号精度。
- 误报率。
- 观测盈亏。
- 回撤。
- ticker 贡献。
- 候选评分和 PnL 是否一致。
- 市场环境。

背后逻辑：

- 系统读取候选解释、订单、持仓和复盘。
- 将候选分数和实际盈亏关联起来。

能达到的效果：

- 不是只看赚钱或亏钱，而是知道为什么赚钱、为什么亏钱。

### 10.7 Alpha 验证

Alpha 验证用于判断策略是否有真实稳定优势。

当前仍在收集样本：

- 复盘天数不足。
- 连续正期望天数不足。
- 成交订单样本不足。
- 闭环交易样本不足。

背后逻辑：

- Alpha ready 不是人工喊通过。
- 系统要看到足够多的运行样本和复盘证据。

能达到的效果：

- 让策略从“感觉不错”变成“有证据支撑”。

## 12. 设置

入口：`/settings`

设置页用于确认系统是否真的接通。

用户可以做什么：

## 13. AI 助手

AI 助手在右下角，默认收起，点击“展开 AI 助手”后打开。

当前动作：

| 动作 | 作用 |
| --- | --- |
| 解释当前页面 | 把当前页面里的数据解释成人能读懂的摘要 |
| 识别组合风险 | 梳理持仓集中度、事件、估值、数据证据中的风险 |
| 生成多/中/空情景 | 给出多头、中性、空头三种研究视角 |
| 起草交易计划 | 生成研究型计划草稿，包括入场条件、失效条件、风控提示 |
| 保存为笔记 | 将 AI 输出保存到研究笔记 |

AI 助手能帮你：

- 快速理解页面。
- 把事件和持仓风险讲清楚。
- 生成研究假设。
- 生成需要人工复核的交易计划草稿。
- 把研究结果保存下来。

AI 助手不能做：

- 不能直接买入或卖出。
- 不能生成可执行订单。
- 不能绕过 Strategy Registry。
- 不能绕过 RiskEngine。
- 不能调用 ExecutionEngine。
- 不能开启实盘。

背后逻辑：

```text
Web AI 助手
  -> /api/mvp/research
  -> LangGraph research workflow
  -> OpenAI-compatible LLM 或确定性本地输出
  -> ResearchResult
  -> 页面展示 / 保存为笔记
```

当前运行态：

- LangGraph 可用。
- Research LLM 已配置且可用。
- AI 不参与交易执行路径。

## 15. 关键名词解释

| 名词 | 用户视角解释 |
| --- | --- |
| Trading Core | 系统自己的交易内核，负责把策略意图变成受风控约束的订单流程 |
| Paper Trading | 模拟盘，用虚拟账户测试策略，不碰真实资金 |
| Candidate | 系统挑出来值得模拟验证的股票候选 |
| Candidate ID | 候选编号，用来追踪这个候选后来有没有下单、赚钱或亏钱 |
| TradeIntent | 策略想交易的意图，还不是订单 |
| RiskEngine | 风控检查器，决定交易意图能不能继续 |
| ExecutionEngine | 执行引擎，在模拟盘里记录订单状态 |
| Event Ledger | 事件账本，记录系统每一步为什么发生 |
| Alpha | 策略经过样本验证后的正净期望能力 |
| Alpha Gate | 防止过早实盘的门禁条件 |
| Expectancy | 平均每笔交易的期望收益 |
| Closed Trade | 已经完成开仓和平仓的闭环交易 |
| Attribution | 归因，解释盈亏来自哪个策略、ticker、候选或市场环境 |
| Backtest | 回测，用历史数据测试策略 |
| LEAN | 专业回测引擎，只用于研究和回测 |
| vectorbt | 快速回测工具，只用于研究和 replay |
| OpenBB | 数据和研究访问工具，不负责下单 |
| LangGraph | AI 投研流程编排工具，不负责交易执行 |
| LLM | 大语言模型，用于解释和研究，不用于自动下单 |
| Shadow | 影子运行，观察策略如果运行会做什么，但不真实下单 |
| Live-small | 小资金实盘验证阶段，当前未开启 |
| Drawdown | 回撤，衡量从高点到低点的损失幅度 |
| Sharpe Ratio | 夏普比率，衡量风险调整后收益质量 |

## 16. 用户每天最终能得到什么

坚持每天运行和复盘后，用户应该得到：

- 每天系统筛出的候选股票。
- 每个候选被选中的原因。
- 模拟下单和成交记录。
- paper account 的权益、现金、持仓和 PnL。
- 哪些订单被风控挡住，以及为什么。
- 哪些候选最终赚钱或亏钱。
- 策略期望值是否持续为正。
- 策略是否仍被样本量、回撤、归因或复盘门禁阻断。
- 是否已经接近 shadow 或 live-small 的人工评审条件。

现阶段最重要的使用原则：

```text
先让系统稳定地产生候选、解释原因、模拟下单、记录盈亏、复盘策略。
等模拟盘连续跑出真实稳定的净期望，再考虑小资金实盘。
```

当前系统仍没有开启实盘。用户应把它当作“可审计的交易研究和模拟盘系统”，而不是自动交易机器人。
